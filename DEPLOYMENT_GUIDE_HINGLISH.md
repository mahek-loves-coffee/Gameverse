# The Gameverse — GitHub + Vercel + Render + Supabase (₹0 setup target)

## Hosting layout

- **Vercel Free:** React/Vite frontend.
- **Render Free:** Express API + Socket.IO multiplayer backend.
- **Supabase Free:** PostgreSQL database.
- Vercel does not host this project's persistent Socket.IO server. Keep the backend on Render and connect it using `VITE_API_URL`.

> ₹0 target: choose Free plans only. Do not add a paid instance, custom domain, add-on, or paid Supabase compute. Free tiers have limits: Render may sleep after inactivity, Supabase Free may pause after a period of inactivity, and in-memory rooms/matches are lost if the Render service restarts. This is suitable for testing, not always-on production. Provider policies can change; check the selected plan before confirming.

## 1) Upload this ZIP to GitHub

1. Create a GitHub repository named `the-gameverse` (Private recommended).
2. Extract this ZIP.
3. Upload the **contents** of the `The Gameverse` folder to the repository root. `package.json`, `vercel.json`, `render.yaml`, `src/`, `server/`, and `shared/` must sit at the root.
4. Never upload `.env`, `data/`, `node_modules/`, passwords, or database connection strings.

## 2) Deploy backend on Render (required for multiplayer)

1. In Render, choose **New → Blueprint** and connect the GitHub repo. It will read `render.yaml`.
2. Select the Free plan only.
3. Add `DATABASE_URL` using the Supabase Postgres connection string (Session Pooler is generally the safer choice for IPv4 hosting). Keep it only in Render's secret environment settings.
4. Add `CLIENT_ORIGIN` = your exact Vercel production URL, e.g. `https://the-gameverse.vercel.app` (no trailing slash). Add preview origins only if you need them.
5. Confirm `SESSION_SECRET` was generated by Render and is a long random value. Keep `NODE_ENV=production`.
6. Deploy and copy the backend URL, e.g. `https://the-gameverse-api.onrender.com`.
7. Test `https://YOUR-RENDER-URL.onrender.com/api/health`. Expected JSON includes `ok: true` and `database: postgres`.

## 3) Deploy frontend on Vercel

1. In Vercel, **Add New → Project**, import the same GitHub repository.
2. Framework: Vite (auto-detected). Build command `npm run build`; output directory `dist`.
3. In Project Settings → Environment Variables, add:
   - `VITE_API_URL` = `https://YOUR-RENDER-URL.onrender.com` (no trailing slash)
4. Deploy. Vercel rebuilds the frontend with the API URL.
5. Copy the Vercel production URL and set that exact URL as Render's `CLIENT_ORIGIN`, then redeploy Render.

## 4) Verify the launch

- Open the Vercel URL and create an account.
- Open a second browser/device and create another account.
- Test login/logout, create room, join room, ready/start, one UNO turn, one Ludo turn, friends, and direct messages.
- If login works but multiplayer doesn't, check Render logs and confirm `CLIENT_ORIGIN` exactly matches the Vercel origin.
- Render Free can sleep; the first request after inactivity may take a while. Active rooms are in memory and are not durable across restarts.

## Local development

Run `npm install`, then `npm run check`, `npm run build`, and `npm run dev`. Without `DATABASE_URL`, local SQLite is used and Vite proxies API/Socket.IO to `localhost:4000`.
